## 1. 一句话与评审结论口径

WeChat Harness 是一套独立的本机桌面 Agent 工作台：用户在微信式会话里指挥 DeepSeek，官方 Desktop Host 执行工具、读写工作区、调度后台任务；需要多人协作时，再开一个同壳的群聊窗口，房间和登录数据与单机会话分开，模型仍用同一把 DeepSeek key。

评审时请按下面四条判定，不要用相邻产品的界面或数据来代替：

| 判定 | 通过条件 |
|---|---|
| 产品形态 | 操作发生在 Electron 窗口 `WeChat Harness` / `WeChat Harness 群聊`，不是 Chrome、Aico 或 `dsh web` |
| 能力来源 | Agent、Session、Workspace、插件、Computer Use 走官方 Desktop Host（本机 `19387`） |
| 交互来源 | 左侧栏、会话列表、气泡、右侧预览、设置卡片来自微信式壳，不是官方原生 Web 布局（除非演示「切换原生 UI」） |
| 隔离 | 不读写、不代理、不占用旧系统 `3080` / `3091` / `5226`；本产品空白启动，不带入旧会话或旧 Key |

## 2. 产品是什么 / 不是什么

### 2.1 是什么

- 本机桌面应用。开发启动后 Dock / Applications 显示 **WeChat Harness**，标识 `ai.ainfinity.wechat-harness`。
- 完整 DeepSeek Harness Desktop 外的一层微信式壳。会话、工作区、权限、插件、Computer Use 仍由官方 Host 执行。
- 双窗口产品：单机聊天在主窗口；群聊版是第二个 Desktop 窗口，入口 `http://127.0.0.1:3191`。
- 空白项目。用户在本应用内另录 Key、另选 Workspace，单独产生会话和群数据。

### 2.2 不是什么

- 不是腾讯官方微信，也不替代、不关闭、不要求退出系统微信。
- 不是浏览器里打开的 Aico、`localhost:3080` 或 `dsh web`。那些可以并存，但不是本产品。
- 不是旧 `dsh-diy-lab` / 3080 微信插件的升级或数据迁移。旧会话、旧 Key、旧群房间不会出现在这里。
- 不是公共 npm 包，也不走官方 DeepSeek Desktop 更新通道。
- 不是「用网页套一层 Electron」冒充 Desktop：主窗口加载 `dsh-app://app/`，Host 在本机 `19387`。

### 2.3 给谁用

| 角色 | 用它做什么 |
|---|---|
| 个人使用者 | 像聊天一样下达任务：写代码、改文件、查网页、生成可预览页面、让 Agent 操作本机（需授权） |
| 小组宿主 | 在本机打开群聊版，建房间、发邀请，让成员用同一套微信式界面协作 |
| 评审人 | 在本机窗口走完「单机工作 + 预览 + 设置启动群聊 + 权限」四条主路径 |

## 3. 评审范围与成功标准

### 3.1 本轮要验收

1. 主窗口能从空白状态完成：选工作区 → 建会话 → 发消息 → 看到思考 / 工具 / 回复。
2. 会话列表第二行是最近消息或状态，不是工作区路径。
3. 无框窗口可从顶部拖动；会话列表可拖宽、拖窄、收到图标栏。
4. 网页或本地工作区 HTML 能在右侧停靠、小窗、沉浸三种预览里打开，Esc 能退出沉浸。
5. 通用设置能启动群聊版；主窗口保持打开；群聊窗口标题为「WeChat Harness 群聊」，壳与主窗口同类（可拖顶部、有会话列表分隔条）。
6. 群聊首次使用出现本机主人初始化或登录卡，而不是白屏。
7. macOS 上 Computer Use 的三项系统权限可以打开；授权并重启后，会话调用电脑操作工具时能够操作本机。
8. 旧 3080 / 3091 若仍在运行，评审过程不得把它们停掉或接到本产品上。

### 3.2 本轮不验收

- 从旧 3080 导入会话、Key、Workspace、群成员、浏览器状态。
- 与旧 3091 房间互通。
- 签名安装包、公证、官方更新源、Windows EV 签名。
- 把 Dock 图标保持常驻（产品不主动固定 Dock）。
- 公共发布或替换官方 DeepSeek Desktop 品牌。

### 3.3 演示环境建议

- 机器：已能运行本仓库的 macOS（当前开发主路径）。
- 密钥：本机已配置可用的 `DEEPSEEK_API_KEY`（用量看板读官方 `/user/balance`）。
- 工作区：一个空目录或演示专用目录，不要打开旧 Harness 工程或本仓库。
- 并存：系统微信可继续运行；旧 3080 可继续运行；评审只操作 WeChat Harness 窗口。

## 5. 双窗口构成

```text
WeChat Harness.app (Electron)
├── 主窗口  dsh-app://app/     → 官方 Desktop Host :19387
│                              微信式单机会话、设置、预览、Computer Use
└── 群聊窗口 http://127.0.0.1:3191/
                               独立登录 / 房间 / 邀请
                               同一套微信壳
                               模型走同一把 DeepSeek key
                               不经过旧 3091
```

两条路径同时存在：

- 关掉群聊窗口，单机聊天继续。
- 关掉主窗口等于退出 Desktop；群聊 sidecar 随 Host 一起结束。
- 设置里点「启动群聊版」时，已打开的群聊窗口会被聚焦；若地址未变则刷新页面，以便拿到最新壳资源。

群聊窗口只接受本机回环 `127.0.0.1:3191` 或 `localhost:3191` 的 `/`，查询参数仅允许 `setup`、`session`。局域网 URL 不会被这个窗口打开。

## 6. 隔离承诺

评审时可用下面这张表当场核对。细节与复测方法见 [ISOLATION.md](ISOLATION.md)。

| 层 | 本产品 | 明确禁止 |
|---|---|---|
| 源码 | 独立 clone / `desktop-wechat-port` | 修改、停止、升级旧 3080 工程 |
| 数据目录 | 开发态写入 `apps/desktop/.desktop-build/development/{home,project,electron-user-data}` | 读取 `~/.dsh/profiles/web`、旧 `.collab-data` |
| 凭据 | 用户在本应用内新录；Key 进 Host credential storage | 从旧 Profile / `.env` / Keychain 继承 |
| Workspace | 用户新选目录 | 默认打开旧项目或本仓库 |
| 端口 | `19387`（Host）、`3191`（群聊） | 占用或代理 `3080` / `3091` / `5226` |
| 群数据 | `DSH_HOME/wechat-collab` | 旧 3091 账号、房间、邀请 |
| 附件 / 调度 | `DSH_HOME/wechat-files`、`wechat-schedules` | 旧 `.file-data` / `.schedule-data` |
| 生命周期 | 本任务不 start/stop 旧进程 | 把旧系统停掉来「证明」新系统 |

旧系统与本产品可以同时开着。同时开着不是缺陷。

## 7. 启动与首次配置

### 7.1 开发启动

仓库根目录：

```sh
pnpm run start:desktop
```

需要重新构建 Host / 客户端 / 群聊壳时用 `pnpm run dev:desktop`。`start:desktop` 跳过构建，直接拉起已有产物。

成功时会出现：

1. `~/Applications/WeChat Harness.app` 启动。
2. 主窗口先显示官方加载页，再进入微信式三栏。
3. 本机 `19387` 对无凭证请求返回 401。
4. 本机 `3191` 对 `/` 返回群聊页（登录卡或会话壳）。

### 7.2 第一次使用主窗口

1. 打开 **通用设置**（左下齿轮）。
2. 在官方设置里写入 DeepSeek API Key（用量看板只认进程里这把官方 Key）。
3. 用左侧「添加工作区」或输入区工具选一个空目录。不要选旧 Harness 工程。
4. 左上「+」创建会话，或直接在已有空白会话里发第一条消息。
5. 标题、副标题可留空：第一条消息后会自动生成。

### 7.3 图片与模型

主窗口支持 PNG / JPG / WebP / GIF。当前默认 Flash 路由带多模态。若切换到不支持图片的模型，发送时报「当前模型不支持图片，请切换到 Vision 模型后重试」。子智能体会话暂不支持图片。

## 8. 界面导览

主窗口从左到右四层。群聊窗口共用同一套壳，登录前是独立登录卡。

### 8.1 左侧功能栏

固定保留：**当前对话**、**已归档会话**、**通用设置**。其余可在设置里隐藏。

| 入口 | 作用 |
|---|---|
| 当前对话 | 回到会话列表 |
| 已归档会话 | 只看已归档 |
| 聊天记录回收站 | 已删除消息，30 天内可恢复 |
| 运行服务 | 查看 / 停止由 Agent 拉起的后台服务；Desktop 与群聊入口自身不会出现在可关闭列表 |
| 任务看板 | 打开官方任务看板插件 |
| 添加工作区 | 原生文件夹对话框 |
| 模式切换 / 模型切换 | 与输入区工具同类的快捷入口 |
| 插件管理 | 把官方插件名翻译成用途说明 |
| 插件商店 / Web UI 插件 | 打开官方对应页 |
| 皮肤中心 / 宠物 | 官方插件入口；未安装时管理页会说明冲突风险 |
| 用量与费用 | 官方 Key 余额 + 本机会话 token |
| 置顶备注 | 可选备注 |

功能栏顺序可拖动，隐藏项可在通用设置「左侧功能栏」里勾回。

### 8.2 会话列表

- 按工作区分组；无工作区会话在分组下方。
- 每行：头像、标题、第二行预览。预览优先最近一条去 Markdown 后的正文，否则是状态：「DeepSeek 正在处理…」「等待你的回答」「开始新的对话」「继续上次的对话」。
- 第二行不会回退成工作区路径或人格副标题。
- 列表右缘可拖动宽度（约 240–440 px）；继续向左收到图标栏（约 78 px）。
- 右键：置顶、标记未读、归档、隐藏、排序。
- 点击头像可改会话资料。

### 8.3 对话区

顶栏：会话头像与标题、工作区 / 模式 / 权限 / 模型摘要、人格、会话详情。群聊房间额外出现工作模式条和成员 AI 参与开关。

消息区：

- 用户与助手气泡；思考过程可展开。
- 工具卡片（含 `visualize_html` / `render_ui` 的内嵌预览与「沉浸模式」）。
- 图片九宫格与大图；文件列表。
- 子 Agent 卡片出现在列表下方，不占左侧会话行；点击在右侧看进度。
- 官方追问（pending question）和群聊冲突确认以卡片出现在流末。
- 运行中显示「正在输入」。
- 上滑后出现「回到底部」。
- 右键或多选：复制、转发 / 合并转发、移入回收站。

输入区：

- 占位「给我发消息…」；Enter 发送，Shift+Enter 换行。
- 运行中发送键变为停止。
- 图片、文件、分支、命令、权限、模型。
- 可拖入或粘贴文件。
- 识别到「每天 / 每周 / 工作日 …」类表述时，先弹出「确认定时任务」，再写入本机调度器并在当前会话回一条确认。

### 8.4 右侧预览

三种呈现，网页、可视化 HTML、子 Agent 共用：

| 模式 | 行为 |
|---|---|
| 停靠 | 贴在对话右侧，左右边可拖；内容铺满当前框并随拖动重排 |
| 小窗 | 角落浮动，可拖位置、八角缩放；关闭控件在页面外 |
| 沉浸 | 铺满对话区；关闭控件在页面外；Esc 退出（访客页拿到焦点时同样有效） |

禁止嵌入的网站走同域浏览改写；仍失败则提示改用独立标签页。

### 8.5 窗口拖动

主窗口与群聊窗口都是无框 Electron 窗。可拖区域在顶部标题条 / 登录壳背景；输入框、按钮、会话列表、预览内部不可拖，以免抢走选择和滚动。

## 10. 核心工作流

### 10.1 像聊天一样做一件开发任务

1. 选工作区，开新会话。
2. 用一句话说目标，例如「在这个目录做一个调休日历页」。
3. 需要改文件时，把权限调到「工作区可写」；需要本机任意操作时再用「完全访问」。
4. 模型调用官方工具。思考和工具状态出现在气泡里，不要切到终端去「找真正的产品」。
5. 若生成 `holiday-calendar.html` 一类页面：聊天里点文件名，右侧打开预览。中文展示名（如「调休日历.html」）在工作区只有一个 HTML 时，仍打开那一个工作区文件；桌面上的拷贝不会代替工作区文件。
6. 预览可改小窗或沉浸。沉浸里点页面空白处后按 Esc，应回到停靠或小窗，而不是把按键吞进页面。

### 10.2 看图说话

1. 输入区点图片，或把截图粘进输入框。
2. 确认当前模型是 Flash / Vision 路由。
3. 发出后气泡带图；点击可大图。

### 10.3 人格只作用于当前会话

1. 顶栏人格按钮。
2. 选模板或导入 `.md` / `.txt` / `SKILL.md`。
3. 保存后仅该会话带上角色、目标、规则、记忆。重启后标题旁头像仍对应当前 Session。

### 10.4 定时在原会话找你

1. 发送类似「每个工作日上午 9 点提醒我看日历」的句子。
2. 确认弹窗里核时间与将要发送的内容。
3. 到点后，同一会话出现由调度器发出的消息；不是系统通知冒充聊天。

### 10.5 转发与清理

1. 长按或右键一条消息 → 转发；或多选后合并转发。
2. 不能转到当前会话。
3. 删除进回收站，左侧入口可恢复；「清空回收站」不可恢复。

## 11. 群聊版

### 11.1 和单机的关系

| | 单机主窗口 | 群聊窗口 |
|---|---|---|
| 打开方式 | 启动应用 | 通用设置 → 启动群聊版 |
| 地址 | `dsh-app://app/` → 19387 | `http://127.0.0.1:3191/` |
| 登录 | Desktop 本机用户 | 群聊账号（首次建主人） |
| 会话数据 | 官方 Session | 房间 / 私聊；不写入旧 3091 |
| 模型 Key | 进程 DeepSeek Key | 同一把；成员看不见明文 |
| 界面 | 微信壳 | 同一套微信壳 |
| 关窗 | 退出产品 | 只关群聊，单机继续 |

群聊 AI 第一跳仍通过 HTTP 调用 19387 的 Desktop Host，所以主窗口对应的 Host 必须在跑。Host 不在时，设置会提示「群聊入口还没起来，单机聊天不受影响」。

### 11.2 第一次打开

1. 主窗口左下角打开通用设置。
2. 卡片「群聊版」说明：与当前单机窗口同时运行；房间和登录分开；模型共用 Key。
3. 点「启动群聊版」。状态应为「已在独立窗口打开，这个单机窗口不用关。」
4. 若本机还没有群聊用户，入口 URL 带 `?setup=` 一次性令牌，页面标题为「初始化本机主人账号」。账号 2–24 字，密码至少 8 位，只存在这台电脑。
5. 没有 setup 令牌时，初始化表单不可用，避免局域网抢注主人账号。从设置启动会带上令牌。
6. 之后打开是「登录你的 Harness」。账号由本机主人发放。

登录卡可拖窗口；账号、密码、按钮区域不可拖。

### 11.3 房间能力（评审可点）

- 新建：单人会话或多人会话。多人可写群说明、进群密码、确认规则（全员 / 群主 / 无冲突自动）、静默等待秒数、是否创建后开启 Agent。
- 邀请：群主或管理员生成链接；链接有次数与有效期。
- 工作模式：
  - **群聊模式**：成员自由聊，AI 不回复、不收集、不执行。
  - **普通讨论**：AI 择机说话，不改代码。
  - **协作执行**：汇总需求、查冲突、确认后执行。
  - **应用服务**：只执行群主应用指令；成员 `@AI` 才反馈。
- 成员可标「参与 / 静默」；在线状态约 35 秒心跳。
- 「只看真人」开关只影响显示。
- 可把多人会话收回为私人会话（邀请失效）。
- 可下载该会话代码包。
- 图片建议小于 1.5 MB；群内图片按当前测试账号保存并同步给房间成员。

### 11.4 群聊与主窗口不要混用的数据

- 主窗口 Session 列表不会自动出现 3191 房间。
- 3191 登录态不会写进官方 Desktop 账户。
- 两边头像等 UI 偏好各自存在本窗口存储里，互不迁移。

## 12. Computer Use

Computer Use 是官方 Desktop 能力，不是微信壳自己实现的一套电脑控制。新 Desktop profile 会插入：

- `@deepseek-ai/dsh-computer-use`
- `@deepseek-ai/dsh-experimental-computer-use-cua-driver-native`

用户仍可在插件管理里关掉这两行。关掉后，会话不再具备本机键鼠与截屏工具。

### 12.1 macOS 权限（必须对着 WeChat Harness）

系统设置里给 **WeChat Harness**（不是「Electron」、不是官方微信、不是 Cursor）打开：

1. 辅助功能（或「设备控制与数据访问」里的辅助功能）。
2. 录屏与系统录音。
3. 输入监控。

改完权限后必须完全退出再开（菜单退出或 ⌘Q）。只关窗口不够，TCC 仍可能绑在旧进程上。

### 12.2 评审时怎样证明它可用

权限打开只表示系统允许，不表示它一直在操作电脑。

1. 重启 WeChat Harness。
2. 开一个权限为「完全访问」的会话。
3. 明确要求「用电脑操作打开某某本机窗口 / 点击某某按钮」。
4. 通过条件：本机出现对应键鼠或窗口变化，会话里出现 Computer Use / Cua 工具记录。
5. 失败时先看权限是否挂在 `WeChat Harness.app`，再看该会话是否关掉了 computer-use 插件。

未授权时，工具会要权限或失败；不要因此判定整个微信壳不可用。

## 13. 设置与管理

通用设置是官方设置面板，顶部插入三张本产品卡片：

1. **界面模式**
   - 微信式 UI：当前产品界面。
   - 原生 DSH UI：官方经典布局。
   只换显示，不换 Session、Workspace、权限、聊天记录。
2. **群聊版**
   启动独立窗口。成功文案必须在窗口已经出现后出现；不得在窗口已打开时报「未能打开」。
3. **左侧功能栏**
   勾选显示；「全部显示」恢复默认。当前对话、已归档、通用设置不能藏。

官方设置页本身仍负责：模型凭据、Workspace、权限默认值、插件启停、语言等。微信壳不复制一份第二设置。

用量与费用：只读当前 Key 的官方余额（可用 / 赠送 / 充值），并按本机会话汇总 token。非 DeepSeek 或未标价的旧模型不编造费用。

## 14. 官方 Harness 能力如何呈现

微信壳不削减官方 Desktop 工具集。模型在会话权限内可以调用官方已加载的工具，包括但不限于：

- 工作区读写、命令执行、本地终端。
- 网页搜索与抓取、浏览器操作。
- 可视化 / UI 渲染（聊天内预览）。
- Office 文档技能（官方 Desktop 内置 Python 运行时）。
- 子 Agent 委派。
- Computer Use（见第 12 节）。
- 插件管理器里启用的第三方工具。

用户侧的变化是呈现，不是能力开关：

- 工具进度在气泡和卡片里，而不是官方时间线主视图。
- 子 Agent 是对话内卡片 + 右侧详情。
- 网页和 HTML 在微信右侧预览，而不是必须打开系统浏览器。
- 任务看板、插件商店仍跳官方页。

评审不要要求「官方 Web 每一块屏幕都在微信壳里原样出现」。要问：同一条官方 Session 在微信壳里能否看完、发完、停得住、预览得到。

## 15. 已知限制

1. **空白项目。** 没有旧会话、旧群、旧 Key。评审当天要重新登录 Key、选目录。
2. **开发启动，不是签名安装包。** 本轮不证明公证、自动更新、Windows EV。
3. **群聊本地工作区 HTML。** 单机聊天点工作区文件名可预览；群聊房间里的 `visualize_html` / 浏览通道可用，但尚未接单机那套「按工作区文件名读 HTML」接口。
4. **群聊 AI 依赖 19387。** 只开着 3191、Host 已退出时，房间还在，执行型 AI 会失败。
5. **预览受网站策略限制。** 部分站点即使走改写通道仍无法嵌入，需独立标签页。
6. **HTML 必须在工作区。** 桌面上一份同名「调休日历.html」不会自动成为预览源。
7. **Computer Use 受 TCC 约束。** 权限挂错应用、未重启、会话关掉插件，都会让操作电脑失败。
8. **用量只认当前进程 Key。** 换 Key 后，历史 token 仍按本机 Session 记，官方余额跟新 Key。
9. **冲突插件。** `dsh-routing-suite`、`DSH-better-sidebar` 等会与每会话模型或微信布局重叠，管理页会写明，不自动卸载。
10. **不固定 Dock。** 退出后图标可以消失；再从 `WeChat Harness.app` 或启动命令打开。
11. **不提供与旧 3091 的邀请互认。** 两套房间两套账号。
12. **皮肤中心 / 宠物。** 只是官方插件入口，不是本产品视觉体系的一部分。

## 16. 评审演示脚本

建议总时长 20–25 分钟。全程只点 WeChat Harness 窗口。

### 准备（2 分钟）

- [ ] Dock 或 Applications 里是 WeChat Harness，不是 Electron / 微信 / Chrome。
- [ ] 主窗口已进入微信式三栏。
- [ ] 需要对照隔离时，另开终端看 `3080` / `3091` 仍可访问（若旧系统当天在跑）。不要重启它们。

### A. 壳与窗口（3 分钟）

1. 按住窗口顶部空白拖动，窗口应移动。
2. 拖会话列表右缘：变宽、变窄、收到头像栏，再拖开。
3. 设置 → 界面模式：切到「原生 DSH UI」再切回「微信式 UI」。会话还在。

### B. 单机工作（6 分钟）

1. 添加一个空工作区，创建会话。
2. 发一条会写文件的中文需求（例如做一个单页 HTML）。
3. 指出思考、工具、最终回复都在同一条对话里。
4. 点聊天里的 HTML 名，右侧停靠预览应铺满；拖预览左缘，页面跟着重排。
5. 切小窗，再沉浸；沉浸中按 Esc 退出。
6. 停一次生成（发送键变方块），确认能停。

### C. 会话管理（3 分钟）

1. 看列表第二行是摘要或状态，不是路径。
2. 改头像或人格，回到列表再进会话，头像仍在。
3. 删除一条消息，打开回收站能看到。

### D. 群聊版（6 分钟）

1. 设置 → 启动群聊版。主窗口不停；状态为已打开。
2. 第二窗标题「WeChat Harness 群聊」。
3. 首次：初始化主人账号。非首次：登录。
4. 登录后拖顶部、拖会话列表，应与主窗同类，不应像「只有中间一块登录卡的旧版」。
5. 建一个多人会话，生成邀请（可只展示链接，不必真的找第二台机器）。
6. 切到「群聊模式」再切回「协作执行」，说明 AI 何时说话。

### E. Computer Use（可选 4 分钟）

1. 出示系统设置里 WeChat Harness 的三项权限为开。
2. 完全重启应用。
3. 在完全访问会话里下一句本机操作指令。
4. 以本机真实变化 + 工具记录为通过；不要只拍权限开关。

### 结束时不要做的事

- 不要为了「干净」去退出官方微信。
- 不要关掉旧 3080「以免干扰」。
- 不要把 Chrome 里的页面当成第二产品。
- 不要要求从旧系统导入一条历史会话。

## 17. 故障与恢复

| 现象 | 先查什么 | 处理 |
|---|---|---|
| 整个应用打不开 | `~/Applications/WeChat Harness.app` 是否还在；`node_modules/electron/dist` 是否被中断的 `pnpm install` 清掉 | 重新 `pnpm install` 后执行 Electron `install.js`，再用 `pnpm run start:desktop` |
| 主窗口一直转圈 | 19387 是否在听；恢复对话框是否报 profile / 端口占用 | `EADDRINUSE` 时退出另一份 DSH Desktop，不要去杀 3080 |
| 设置说群聊未能打开，但窗已经在 | 旧逻辑把 `window.open` 被拒绝当成失败 | 当前应以 IPC 打开并以「已在独立窗口打开」为准；重开设置再点一次应聚焦旧窗 |
| 群聊白屏 | 控制台 React #31（双 React 运行时）或窗口还在用旧 `collab-ui.js` | 关闭该窗，设置里再启动（或 ⌘R）。sidecar 对 JS/CSS 为 `no-store` |
| 群聊仍是「第一版」（不能拖顶栏） | 3191 仍在提供过期 bundle | 重新 `bundle:collab-ui` 后刷新群聊窗 |
| 点「调休日历.html」打不开 | 工作区文件名是 `holiday-calendar.html`，桌面拷贝不在工作区 | 保证工作区根目录有那一个 HTML；中文名在「只有一个 HTML」时仍应对上 |
| Computer Use 不动 | 权限给错应用；未 ⌘Q；插件被关；会话不是完全访问 | 对 WeChat Harness 打开三项权限并重启 |
| 用量读失败 | 没有进程 Key 或官方余额接口不可达 | 在官方设置写入 Key；不把失败当成壳坏了 |
| 群聊执行型 AI 失败 | 19387 Host 已退出 | 先恢复主窗口 / Host，再在房间重试 |

原生致命故障会弹出官方恢复框：退出、重启、禁用第三方插件、备份 profile patch。微信壳没有第二套应急页。
